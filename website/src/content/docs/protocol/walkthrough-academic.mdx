> Complete walkthrough of a 50-paper academic literature review using RAMP v1.0. Demonstrates batch DOI queries, mixed free/paid/subscription offers, retraction detection, and the `ramp-academic-v1` extension profile. Every field name and message structure matches the current `ramp.proto`.

## Scenario

A university AI research agent needs 50 academic papers for a literature review on "transformer architectures in medical imaging." The papers span four sources:

| Source | Type | Papers | Pricing |
|---|---|---|---|
| **arXiv** | Open Access (Gold) | 12 | Free |
| **University subscription** | Institutional deal via Elsevier | 20 | $0.00 (subscription) |
| **Elsevier** (no subscription) | Paywalled | 17 | $1.50/article |
| **Springer Nature** | Paywalled, retracted | 1 | $1.50/article (flagged) |

The agent carries a Biscuit delegation token from the university, granting `academic:*` scope. The Broker resolves DOIs via OpenAlex, discovers Exchanges via `ramp.json`, and uses the `ramp-academic-v1` extension profile to access version, OA status, and retraction metadata.

**Six-step flow:**

```
Discovery → ResourceQuery → ResourceResponse → Broker Selection → Batch ExecuteTransaction → ReportUsage
```

All three publishers route through the same academic aggregator Exchange (`exchange.scholarsgate.com`). RAMP gives them a standard protocol for what they already do. The Broker sends a single batch query instead of querying each publisher separately.

**Key fields in this request:**

- **`ResourceQuery.uris`** — 50 DOIs in `doi:` URI scheme. The Exchange resolves these against its catalog. DOIs are the universal dedup key for academic content: the same paper on arXiv and Elsevier shares the same DOI (or is linked via `academic.related_works`).
- **`requester.scopes`** — `["academic:*"]` declares full academic access. The Exchange will check this against the Biscuit token to determine subscription entitlements.
- **`delegation`** — A Biscuit token signed by `stanford.edu`'s Ed25519 key. The authority block contains:
  ```
  user("inst-sub-stanford-2026");
  scope("academic:*");
  max_accesses(100000);
  quota_period_hours(720);
  expires(2026-12-31T23:59:59Z);
  ```
  The Exchange verifies the Biscuit offline (no call to Stanford needed), confirms the subscription covers Elsevier content, and returns zero-cost offers for covered papers.
- **`supported_profiles`** — `["ramp-academic-v1"]` tells the Exchange to include academic-specific `ext` fields (OA status, version, retraction status) and attestation claims. Without this declaration, the Exchange MAY skip expensive metadata computation like retraction checking.

**What the Broker learns from the 50 OfferGroups:**

### Offer Categories

The Exchange classified each of the 50 DOIs into one of four categories based on the publisher's access model and the Biscuit delegation:

| Category | Count | Pricing Model | Rate | Key Signal |
|---|---|---|---|---|
| **Free OA (arXiv)** | 12 | `PRICING_MODEL_FREE` | $0.00 | `academic.oa_status: "gold"`, `academic.version: "preprint"` |
| **Subscription (Elsevier)** | 20 | subscription (FREE + subscription scope) | $0.00 | `subscription_id: "inst-sub-stanford-2026"` |
| **Paid (Springer + Elsevier)** | 17 | `PRICING_MODEL_PER_UNIT` | $1.50 | No subscription match, `academic.oa_status: "closed"` |
| **Retracted (Springer)** | 1 | `PRICING_MODEL_PER_UNIT` | $1.50 | `academic.retraction_status: "retracted"` in `ext_critical` |

### Extension Profile Fields (`ramp-academic-v1`)

Because the ResourceQuery declared `supported_profiles: ["ramp-academic-v1"]`, every offer includes academic-specific metadata:

- **`academic.oa_status`** — Open Access classification. Values: `gold` (fully OA), `green` (author self-archived), `hybrid` (OA in subscription journal), `bronze` (free-to-read but no license), `diamond` (no APC), `closed` (paywalled). The Broker uses this to prefer free sources.
- **`academic.version`** — Article lifecycle stage. Values: `preprint` (author's original), `aam` (accepted author manuscript), `vor` (Version of Record, publisher-formatted). The Broker prefers VoR when available, falls back to preprint.
- **`academic.retraction_status`** — Publication integrity status. Values: `active` (valid), `retracted` (withdrawn), `expression_of_concern` (under investigation). When `retracted` appears in `ext_critical`, the consumer MUST understand retraction semantics or reject the offer.
- **`academic.peer_review_status`** — Whether the paper has been peer-reviewed. Values: `peer_reviewed`, `not_peer_reviewed`. Useful for weighting evidence quality.

### Retraction Flagging

The retracted paper (DOI `10.1038/s41592-024-02467-x`) is immediately identifiable:

1. **Attestation claim**: `academic.retraction_status: "retracted"` in `ResourceAttestation.claims`, signed by `springer.com`.
2. **Ext field**: `academic.retraction_status: "retracted"` in `Offer.ext`.
3. **Critical signaling**: `ext_critical: ["academic.retraction_status"]` — the consumer MUST understand retraction semantics. An agent that does not support `ramp-academic-v1` would reject this offer with `OFFER_ABSENCE_REASON_UNKNOWN_CRITICAL_EXTENSION` rather than silently consuming a retracted paper.
4. **Offer.title**: Prefixed with "RETRACTED:" as a human-readable signal.

### Content Identity and Dedup

Every offer carries a `ResourceIdentity` with:
- **`doi`** — The DOI serves as the universal dedup key. If the same paper were available from multiple Exchanges (e.g., via a different aggregator), the Broker groups offers by DOI to compare pricing.
- **`content_hash`** — SHA-256 hash for post-delivery verification. Because `resource_mutability` is `RESOURCE_MUTABILITY_STATIC` for all academic papers (published articles do not change — corrections and retractions create new resources), the agent SHOULD verify the hash on delivery.
- **`canonical_url`** — The publisher's authoritative URL. Different from the DOI URI but resolves to the same resource.

### Subscription Detection

For the 20 Elsevier papers covered by Stanford's institutional subscription:
- subscription (FREE + subscription scope): `pricing.model` is `PRICING_MODEL_FREE` with `rate: 0`, and the term carries `scopes: ["subscription:inst-sub-stanford-2026"]`
- `subscription_id` matches the Biscuit token's `principal_id` (`inst-sub-stanford-2026`)
- `subscription_quota` shows remaining capacity (76,520 of 100,000 accesses this period)
- The Exchange verified the Biscuit offline — no call to Stanford's identity provider was needed

## Step 4 — Broker Selection

The Broker applies a cost-minimization strategy across all 50 OfferGroups:

### Selection Rules

1. **Exclude retracted papers** — The retracted paper is flagged to the research agent. The agent decides whether to exclude it from the review or include it with a retraction annotation.
2. **Prefer free OA** — 12 arXiv papers at $0.00 each.
3. **Prefer subscription** — 20 Elsevier papers at $0.00 each (institutional deal).

1. **Signature verification** — verifies each `offer_signature` is its own Ed25519 signature (stateless, no stored offers).
2. **Agent authentication** — verifies the request's RFC 9421 HTTP Message Signature (alg=ed25519, carried in the HTTP headers) against the agent's published public key at `cs.stanford.edu/.well-known/ramp.json` (`role=ROLE_AGENT`).

6. **WAL write** — records all 49 transactions in the write-ahead log before generating signed URLs (write-before-sign invariant).
7. **Signed URL generation** — generates 49 HMAC-SHA256 signed URLs, each binding `agent_id` and `txn_id`.

## Protocol Summary

| Step | RPC | Free OA (12) | Subscription (20) | Paid (17) | Retracted (1) |
|------|-----|---|---|---|---|
| 1 | -- | `ramp.json` discovery | `ramp.json` discovery | `ramp.json` discovery | `ramp.json` discovery |
| 2 | `DiscoverResources` | `Requester` with `academic:*` scope | Same + Biscuit delegation | Same | Same |
| 3 | -- | Offers at $0, `oa_status: "gold"` | Offers at $0, `subscription_id` set | Offers at $1.50 | Offer with `retraction_status: "retracted"` in `ext_critical` |
| 4 | -- | Broker selects (free) | Broker selects (free via sub) | Broker selects (cheapest) | Broker flags and excludes |
| 5 | `ExecuteTransaction` | Batch, cost $0 | Batch, cost $0, sub quota decremented | Batch, cost $1.50/ea | Not transacted |
| 6 | `ReportUsage` | Aggregated report, 614K tokens across 49 papers | | | |

**Authentication at every step:**
- **Agent to Exchange**: signed with an RFC 9421 HTTP Message Signature (alg=ed25519) in the HTTP headers
- **Institutional delegation**: Biscuit token signed by `stanford.edu`'s Ed25519 key (offline-verifiable)
- **Exchange to Agent**: `exchange_signature` on each Offer (Ed25519, stateless verification)
- **Signed URLs**: HMAC-SHA256 (Exchange-CDN shared secret, agent identity bound)
- **Content integrity**: SHA-256 hash verification on all 49 delivered PDFs (`RESOURCE_MUTABILITY_STATIC`)

**Key academic-specific capabilities demonstrated:**
- **DOI as universal dedup key** -- cross-exchange resource identification
- **Mixed pricing in single batch** -- FREE + subscription (FREE + subscription scope) + PER_UNIT in one transaction
- **Institutional subscription via Biscuit** -- offline-verifiable delegation, no call to Stanford
- **Retraction flagging via `ext_critical`** -- consumers MUST understand retraction semantics or reject
- **`ramp-academic-v1` profile** -- OA status, version lifecycle, peer review status, retraction metadata
- **Aggregator as Exchange** -- one Exchange serves content from multiple publishers
